## Context

astroterm (v1.2.0, MIT, C99 + ncurses + argtable, Meson, Unity tests, CI on Linux/macOS/Windows-MSVC) renders a
stereographic all-sky dome. `main.c` owns a single render loop: update positions → render layers → `getch()`
(only `q`/`ESC` handled) → `doupdate()` → sleep. All options are parsed once into `struct Conf`. Colors are set up
only when `-c` is passed. Simulation time is advanced by adding the *nominal* frame period each frame
(`julian_date += dt × speed`), so every slow frame and every laptop sleep makes the sky fall permanently behind
the wall clock (upstream #77). Nothing touches the network today.

Constraints: stay C99 and MSVC-compilable; add no link-time dependency; keep upstream's style (`.clang-format`,
Allman braces, 120 columns); every new piece must be separable into its own upstream PR.

## Goals / Non-Goals

**Goals:**
- Every display option is live-toggleable; `?` explains them.
- A red night-vision mode usable at a dark site.
- ISS/Tiangong and Starlink rendered with SGP4 accuracy (≪ 0.1° for fresh TLEs), offline-first.
- Motion vectors, time controls, next ISS pass, constellation names.
- Unit-tested maths; an end-to-end smoke test driving the real binary in tmux.

**Non-Goals:**
- Deep-space SGP4 (SDP4): no geostationary or Molniya objects.
- Magnitude/brightness prediction for satellites (we classify sunlit vs eclipsed only).
- Arbitrary satellite catalogs, satellite search/selection, config files (listed in the idea backlog).
- Windows background download (Windows reads the cache only).
- Perspective/horizon projection.

## Decisions

### D1. Own a small near-Earth SGP4 in C, verified against python-sgp4
Write `src/sgp4.c` (~350 lines): Vallado's 2006 revision of SGP4 (`sgp4init` + `sgp4`, near-Earth branch
only, WGS-72, `afspc` operation mode off), returning TEME position/velocity in km and km/s.
*Alternatives:* vendoring Vallado's C++ (would add C++ to a C project and has unclear licence text); linking an
external library (new dependency, unavailable on MSVC CI). *Guard:* golden vectors generated by `python-sgp4`
(MIT, a direct port of Vallado) at several `tsince` values for ISS, Starlink and a high-drag set, checked to 10 m.
Periods ≥ 225 min are rejected at init (they would need SDP4).

### D2. Topocentric conversion reuses the existing equatorial pipeline
TEME ≈ true-equator/equinox of date, so `r_obs(TEME)` is the observer's WGS-84 ECEF position rotated by GMST
(`greenwich_mean_sidereal_time_rad`, already in `astro.c`). The topocentric vector `r_sat − r_obs` becomes RA/Dec
via `equatorial_rectangular_to_spherical`, then az/alt via the existing `equatorial_to_horizontal`. Polar motion
and ΔUT1 are ignored (< 1″ and < 0.9 s). Verified against Skyfield to 0.1°.

### D3. Sunlit test: cylindrical Earth shadow
With `ŝ` the unit geocentric Sun vector (from the existing Sun computation, AU → direction only), a satellite at
`r` is eclipsed iff `r·ŝ < 0` and `|r − (r·ŝ)ŝ| < 6378.137 km`. Penumbra is ignored: fine for a dot that is either
bright or dim.

### D4. Data: cache-first, refreshed by a spawned `curl`
`src/tle_cache.c` resolves the cache dir (`$ASTROTERM_CACHE_DIR` › `$XDG_CACHE_HOME/astroterm` ›
`~/.cache/astroterm`), loads `stations.tle`/`starlink.tle`, and when a *wanted* feed is missing or older than 12 h,
starts `curl -fsSL --max-time 60 -A astroterm/<ver> -o <feed>.tmp <url>` with `posix_spawnp` (argv array, no
shell; stdin/stdout/stderr → `/dev/null` so the child never writes over the curses screen). Each frame polls
`waitpid(pid, WNOHANG)`; on exit status 0 the parent parses the `.tmp`, and only if it yields ≥ 1 valid set
renames it over the feed and swaps the catalog. Failures back off 15 min. On quit, a running child is killed
and its `.tmp` removed.
*Alternatives:* libcurl (link dependency, packaging pain, MSVC CI); raw sockets (no TLS);
blocking `system()` (freezes the sky for 3–4 s on the 1.8 MB Starlink feed).
*Why 12 h:* CelesTrak updates GP data every ~2 h and blocks clients that re-download unchanged data; LEO
TLEs stay visually accurate for days.

### D5. Sim clock anchored to the realtime clock
`src/sim_clock.c`: `{anchor_jd, anchor_wall, speed, paused, last_nonzero_sign}`. `jd(now) = anchor_jd +
(now − anchor_wall) × speed / 86400`. Any change (pause, speed step, jump-to-now) first re-anchors at the current
instant. The wall reference is `timespec_get(TIME_UTC)` (C11; macOS, glibc, MSVC 2015+), a *realtime* clock, so
sleep/wake and slow frames cannot cause drift (the monotonic `CLOCK_MONOTONIC_RAW` used by the frame limiter
stops during sleep on macOS). The frame limiter keeps using `stopwatch.c`. Pure functions take `now` as a
parameter, so they are unit-testable without sleeping.

### D6. Input is a pure state transition
`src/controls.c`: `enum Action controls_handle_key(int ch, struct Conf *cfg, struct UiState *ui, char *toast,
size_t n)` mutates config/UI state and writes the toast text; it never calls curses. `main.c` performs side
effects the action requests (resize the metadata window, re-apply the palette, start a download, quit). Unit
tests cover every key. `keypad(stdscr, TRUE)` and `set_escdelay(25)` make arrows single keys and keep `ESC` snappy.

### D7. Night vision is a palette swap, not per-call-site logic
Colors are initialised whenever the terminal supports them (not only with `-c`); `config.color` decides whether
object pairs are *used*. Named pairs: 1–8 upstream colors, plus `PAIR_SAT_LIT`, `PAIR_SAT_DARK`, `PAIR_STATION`,
`PAIR_DIM` (grid, lines, vectors, names, UI chrome), `PAIR_UI`. `palette_apply(night)` calls `init_pair` for every
named pair: day mode restores the normal definitions; night mode maps bodies/stations → bright red, stars/labels
(the background pair) → medium red, and the `SAT_*`/`DIM` pairs → dim red, all on black. With ≥ 256 colors the tiers
are xterm 160/124/88; with 8 colors all tiers are `COLOR_RED` and the dim tier adds `A_DIM`. Pairs are always
used while night vision is on, so the tiers apply even with `-c` off. `wbkgd()` on `stdscr` and every window
paints the full screen black. Upstream render functions stay untouched apart from choosing a named pair.

### D8. Layer order and one braille layer per frame
Order, bottom to top: Starlink dots → motion vectors → constellation names → stars → constellation figures →
planets → Moon → stations → grid/cardinals → toast → help modal. The shared braille mask buffer is cleared once
per frame in the main loop (today it is cleared only when constellations are drawn, so masks leak between frames
when they are off). Starlink dots write single dots into that buffer via a sub-cell variant of `polar_to_win`.
Writes are bounds-checked against the buffer size.

### D9. Bounded satellite cost
Stations are propagated every frame (two objects). Starlink is propagated when ≥ 250 ms of wall time has passed
or sim time has moved > 10 s since the last update. Positions are cached as az/alt plus a look-ahead az/alt for
vectors (D11). About 10,700 objects × 4 Hz ≈ 43k SGP4 calls/s, a few percent of one core.

### D10. Next-pass prediction is cached, not polled
`predict_next_pass()` scans forward in 30 s steps up to 72 h, then refines the rise/culmination to 1 s. The
result `{computed_at, rise, culmination_alt, set}` stays valid while `computed_at ≤ jd < set`. It is recomputed
when sim time leaves that window, when the station catalog is replaced, and at most twice per wall second (so
3600x fast-forward cannot turn it into a hot loop). About 8,640 propagations per scan, ≈ 5 ms.

### D11. Motion vectors
Bodies: recompute the Sun/planet/Moon az/alt at `jd + sign × 1 h` with the existing functions (≈ 10 extra
evaluations per frame). Satellites: `r' = r + v·Δt` in TEME with `Δt = sign × 30 s`, converted with GMST at
`jd + Δt`, so no second SGP4 call. Lines are drawn only when both ends project inside the dome, with the far end
pulled back to the horizon otherwise, capped at R/3 and skipped when shorter than one cell.

### D12. Module map (new files)
`sgp4.{c,h}` (maths only) · `satellite.{c,h}` (TLE parse, catalog, topocentric, sunlit, passes) ·
`tle_cache.{c,h}` (paths, freshness, spawn/poll) · `sim_clock.{c,h}` · `controls.{c,h}` ·
`overlay.{c,h}` (help modal, toast, palette) · `constell_names.{c,h}`. `main.c` gains an `AppState` and
wiring only.

### D13. Upstream PR slicing
1. Live keys + help modal + toast + keypad fix. 2. Sim clock + time controls (fixes #77). 3. Night vision.
4. SGP4 + stations + next pass (closes #46). 5. TLE cache/fetch + Starlink. 6. Motion vectors.
7. Constellation names (closes #35). The fork branch keeps one commit per slice, in this order.

## Risks / Trade-offs

- [SGP4 transcription bug] → golden vectors from python-sgp4 across several sets and ±3 days; tests fail at 10 m.
- [CelesTrak rate limiting or URL change] → 12 h TTL, 15 min failure back-off, clear toast, cache kept.
- [Stale TLEs in the field] → the toast shows data age; above 7 days it warns that positions may be minutes off along-track.
- [Hostile/garbled feed] → strict fixed-column parsing with checksums; names reduced to printable ASCII; the feed is swapped only after validation.
- [Child process writes to the terminal] → all three stdio fds redirected to `/dev/null` in the spawn file actions.
- [CPU on slow machines] → 4 Hz Starlink cadence; measured in the smoke test; the cadence is one constant to tune.
- [Palette swap on exotic terminals] → uses only `init_pair` (never `init_color`), so the user's terminal palette is never modified.
- [Upstream may not want network features] → slices 1–4 are network-free (stations can be fed by the cache); the network-dependent part is isolated in slice 5.
- [Key clashes with future upstream keys] → keys mirror existing short flags wherever one exists (`c C g u b m`).
- [Visual clutter with ~500 Starlinks up at once] → single braille dots, beneath stars, "sunlit only" filter (`X`).

## Migration Plan

No migration: all existing flags keep their meaning and defaults, except that stations are on by default in the
fork (a cache-only first run shows nothing and fetches in the background). Rollback: `--offline`, or toggle any
layer off live.

## Open Questions

- Should stations default to on upstream (it implies a network request on first run)? Proposed: yes in the fork,
  maintainer's call upstream.
- Constellation-name collisions with bright-star labels: accepted for now (names are dim and beneath).
